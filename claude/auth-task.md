### Implementasi

- **`App\Services\Mail\EmailService`** (baru) - wrapper `send(string $to, Mailable $mailable): array` murni "kirim mailable ke alamat ini", pola sama seperti `App\Services\Kapso\KapsoWhatsAppService` (satu concern, tidak tahu apa-apa soal OTP) - siap dipakai ulang untuk email lain nanti (reset password, notifikasi, dst) tanpa perlu service baru. `App\Mail\OtpMail` (Mailable biasa, BUKAN `ShouldQueue`) + `resources/views/emails/otp.blade.php` (markdown mail bawaan Laravel, `<x-mail::message>`/`<x-mail::panel>`, sudah jalan tanpa perlu `vendor:publish`) - sengaja synchronous (bukan di-queue) supaya user tidak perlu menunggu `queue:work` jalan untuk menerima kode OTP-nya (lihat juga menu Status Server yang baru dibuat sebelumnya - queue worker bisa saja sedang mati).
- **Login sekarang 2 langkah**, kredensial TIDAK langsung memanggil `Auth::login()` lagi:
  1. `AuthenticationController::login()` - `AuthenticationService::validateCredentials()` (cek email/username+password TANPA login), lalu `hasActiveSessionElsewhere()` (lihat poin satu-sesi di bawah), lalu `sendOtp()` (generate 6 digit random, `Hash::make()` disimpan ke `users.otp_code_hash` + `otp_expires_at = now()->addMinutes(10)`, kirim via `EmailService`) dan simpan `user_id`+`remember` sementara di session (`login_otp_user_id`/`login_otp_remember`), redirect ke halaman OTP.
  2. `AuthenticationController::verifyOtp()` - `Hash::check()` kode + cek `otp_expires_at` belum lewat, baru panggil `AuthenticationService::completeLogin()` yang MELAKUKAN `Auth::login()` + `session()->regenerate()` + set `current_session_id`/`last_activity_at` + hapus kolom OTP.
  - Endpoint `login/otp/resend` (throttle `3,1`) generate+kirim kode baru (meng-overwrite hash lama, kode lama otomatis tidak valid lagi). Endpoint verifikasi sendiri di-throttle `6,1` (brute-force 6 digit lewat form web).
- **"Satu sesi aktif per akun" ditegakkan di TITIK LOGIN, bukan lewat menendang sesi lama di tengah jalan**: `AuthenticationService::hasActiveSessionElsewhere()` cek `users.current_session_id` tidak null DAN `last_activity_at` belum lebih dari `IDLE_TIMEOUT_MINUTES` (60) yang lalu - kalau device lain masih "aktif" menurut definisi itu, login BARU (di device manapun, termasuk device yang sama sekalipun) ditolak dengan flash `session('error')` yang otomatis muncul sebagai modal lewat `<x-alert-modal/>` (ditambahkan ke `_modern-login.blade.php`, sebelumnya belum ada di halaman itu) - PERSIS sesuai instruksi "gagal masuk...dalam bentuk modal". Sempat dicoba pendekatan LAIN (`App\Http\Middleware\EnsureAuthSessionIsFresh` membandingkan `current_session_id` tersimpan dengan `session()->getId()` request SAAT INI, menendang paksa sesi yang "kalah") tapi DIBATALKAN - selain bukan yang diminta (instruksinya login baru yang gagal, bukan sesi lama yang ditendang), pendekatan itu ternyata rapuh terhadap cara Laravel test client bekerja (lihat catatan panjang di docblock middleware itu) dan bikin puluhan test lain di seluruh suite (yang melakukan >1 request `actingAs()` berturut-turut) salah ke-logout di tengah jalan.
- **Idle timeout 1 jam** (`AuthenticationService::IDLE_TIMEOUT_MINUTES`) ditegakkan di `App\Http\Middleware\EnsureAuthSessionIsFresh` (didaftarkan global di grup `web`, lihat `bootstrap/app.php`) - tiap request terautentikasi me-refresh `last_activity_at`; begitu selisihnya lebih dari 60 menit, user di-logout paksa (`session()->invalidate()`) dan `reauth_user_id`+`reauth_intended_url` ditaruh di sesi BARU (harus SETELAH invalidate, karena invalidate menghapus semua data sesi lama), redirect ke `reauthenticate.show`. User yang belum pernah tercatat (`last_activity_at` masih null, mis. baru saja register - alur register sengaja TIDAK diubah, tetap `Auth::login()` langsung tanpa OTP karena bukan yang diminta) otomatis "sembuh sendiri" di request pertama, tidak kena logout dadakan.
- **`App\Http\Controllers\Auth\ReauthenticateController`** (baru, route `GET/POST reauthenticate`) - input ulang password SAJA (TIDAK lewat OTP lagi, sesuai instruksi), verifikasi `Hash::check()` password lalu `AuthenticationService::completeLogin()` (fungsi yang SAMA dipakai jalur OTP normal - login "resmi" cuma pernah terjadi di satu tempat), redirect ke `reauth_intended_url` yang tersimpan (kembali ke halaman yang sedang dibuka saat idle timeout kena).
- **Satu template `resources/views/auth/_modern-two-steps.blade.php`** dipakai untuk KEDUA halaman (parameter `$mode`: `'otp'` atau `'password'`) sesuai instruksi eksplisit "pakai template modern-two-steps.blade.php juga, ganti field jadi password" - chrome (dropdown bahasa, panel kanan) disalin dari `_modern-login.blade.php` supaya konsisten. File demo asli `modern-two-steps.blade.php` di-rename/dihapus (diganti `_modern-two-steps.blade.php`) mengikuti konvensi rename `_` yang sudah ada di file ini - dicek dulu tidak ada referensi lain ke nama lama (cuma ada di `sidenav-demo-reference.blade.php.bak`, tidak live). Input OTP pakai 6 kotak digit terpisah dengan auto-advance/paste-support (vanilla JS, digabung ke satu hidden input `otp` sebelum submit) - beda dari demo aslinya yang cuma 4 kotak, disesuaikan ke 6 digit untuk keamanan yang lebih wajar.
- **Dwibahasa**: mengikuti pola yang SAMA seperti sudah ada di `satsln.blade.php` vs `sats-ln-detail.blade.php` (lihat `claude/permohonan-task.md`) - teks di `_modern-two-steps.blade.php` (halaman UI biasa) pakai `__()` tunggal + `lang/en.json` (bukan tampil dwibahasa berdampingan, karena bukan dokumen resmi), semua string baru (termasuk subjek+isi email OTP) ditambahkan ke `lang/en.json`.
- **Migration baru** nambah 4 kolom ke `users`: `otp_code_hash`, `otp_expires_at`, `current_session_id`, `last_activity_at` (semua nullable, tidak ada constraint unik/FK - murni data bookkeeping per user).

- **Catatan teknis test yang ditemukan selama kerja ini**: Laravel test client (`$this->get()/post()`) TIDAK meneruskan cookie sesi antar panggilan terpisah dalam satu test (beda dari browser sungguhan), TAPI `Auth::user()` (guard) dan DATA sesi (`session()->put()/get()`) tetap "bertahan" antar panggilan itu karena singleton container tidak dibangun ulang antar call dalam satu test method - HANYA `session()->getId()` yang benar-benar berubah tiap panggilan. Ini sebabnya alur OTP 2-langkah (`post('/login')` lalu `post('/login/otp')`) tetap bisa ditest apa adanya, tapi test apapun yang butuh MEMBANDINGKAN id sesi antar request terpisah (skenario yang tadinya mau dipakai untuk fitur "tendang sesi lama") harus pakai `actingAs()`/`withSession()` untuk state satu-request, bukan mengandalkan 2 panggilan HTTP berurutan.
